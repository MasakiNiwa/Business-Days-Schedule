# Business Days Schedule

営業日を考慮したカレンダー。

日本の祝日を自動で取り込み、**反復ルール**（毎月25日／月末営業日／第5営業日／第2・第4火曜 など）から
予定を導出し、休祝日にかかった予定を**前営業日・翌営業日へ自動でずらして**表示します。

ルールを持たない単発の予定登録は、意図的に対象外としています。

- 📄 **[仕様書 docs/SPEC.md](docs/SPEC.md)**

**公開先**: https://masakiniwa.github.io/Business-Days-Schedule/

|---|---|

| 表示層 | `src/ui/` — 月カレンダー、一覧、ルール一覧、編集フォーム、日付詳細、設定、ヘルプ |

サンプルは種類ごとに分かれており（基本セット／税務・届出／売上・入金／支払・振込／会議・報告）、
**使い始めたあとでも追加できます**。「内容を選ぶ」で必要な予定だけ追加できます。追加しても既存のルールは消えません。

## 使い方

1. **ルールを追加** — 給与・支払・締め日・会議・自由入力のひな型から始め、
   休業日にあたったときの補正（前倒し・後ろ倒し・**前後の両方**・近い方・補正なし）を決めます。
   保存欄に設定の要約と直近3回の日付が出ます。必要なら「次の10回をすべて見る」を開けます。
   取引先ごとに前倒し・後ろ倒しが分かれる入金予定などは「前後の営業日の両方へ」を選ぶと、
   1つのルールで両側を押さえられます。
2. **月を移動する** — 年月の両横の `‹` `›`、または年月をクリックして月を選べます。
   スマートフォンではカレンダーを左右にスワイプしても移動できます。
3. **カレンダーを読む** — 補正された予定には `←10` `→10` が付きます。`←` は前倒し、
   `→` は後ろ倒し、数字は補正前の日です。予定名は省略せず、セルは中身に合わせて伸びます。
   セルのどこをクリックしても当日の詳細が開きます。
4. **営業日を定義** — 右上の設定（⚙）から、週末の曜日・祝日を休むか・年末年始などの休業期間・
   臨時休業日・祝日出勤日を指定します。「自社」と「銀行」を別々に持てるので、
   社内の締めと振込を使い分けられます。
5. **決算月を設定する** — 設定の「決算月」を変えると、`決算月基準` のルール
   （法人税・消費税の申告、期首、中間申告、四半期末）の日付が**まとめて追従します**。
   3月決算なら申告期限は5月末、12月決算なら翌年2月末、というように自動で変わります。
6. **一覧で先を見る** — 右上の「一覧」に切り替えると、今日から 30／90／180／365 日先までの
   予定が時系列で並びます。日付をクリックすればその日の詳細、予定名をクリックすれば
   そのルールの編集が開きます。
7. **印刷する** — カレンダー・一覧のどちらもそのまま印刷できます。操作ボタンは省かれ、
   白地・黒文字で出力されます。アプリ名と版は印刷しません（年月・予定・営業日数・出典は残ります）。
8. **会社のカレンダーへ取り込む** — 設定から、期間を指定して iCalendar (.ics) または
   CSV で書き出せます。Google カレンダー・Outlook などに取り込めます。
   繰り返しの設定そのものは渡らず、その期間の日付として展開されるので、
   期間が過ぎたら書き出し直してください。
9. **バックアップ** — 設定の「エクスポート」で JSON に書き出せます。
   データはブラウザの localStorage に保存されるため、端末を移るときは書き出してください。

ルールの一覧・追加、サンプルの追加は右上の **ルール** ボタンから開きます。
配色は **◐** ボタンで 自動 / ライト / ダーク を切り替えられます。
操作に迷ったら **?** ボタンから画面内ヘルプを開けます。

## 祝日データについて

一次ソースは [`holiday-jp/holiday_jp`](https://github.com/holiday-jp/holiday_jp) の `holidays.yml`
（UTF-8、1970〜2050年、振替休日・国民の休日を収録）。
内閣府CSVへの依存はありません。毎週月曜03:17（日本時間）を予定時刻として、
取得・検査したデータをアプリと一緒にGitHub Pagesへ公開します。
ブラウザは起動時に公開済みデータを取得し、通信できない場合は保存済みデータを使います。
詳細は [仕様書 §3](docs/SPEC.md#3-祝日データ)。

## 開発

```bash
npm install
npm run dev        # 開発サーバー
npm test           # テスト
npm run typecheck  # 型チェック
npm run build      # 本番ビルド
```

祝日データの手動更新:

```bash
npm run holidays         # holidays.yml → public/data/holidays.json
```

## 開発（続き）

```bash
npm run e2e:install  # E2E 用ブラウザの用意（初回のみ）
npm run e2e          # 本番ビルドに対するブラウザテスト
```

E2E は `dist/` を素の静的配信で動かします（`scripts/serve-dist.ts`）。
GitHub Pages と同じ条件に近づけ、公開後にだけ壊れる不具合を拾うためです。

## 外部カレンダーへ再取り込みするとき

ICS/CSVは自動同期ではなく、書き出した時点の予定です。取り込み先によって再取り込みの動作は異なります。
v1.1.0ではICSの予定識別子を変更したため、旧版の予定と重複しないよう、専用カレンダーで入れ替えるなど取り込み先で確認してください。

## オフライン対応

一度開いたあとは、通信が無くても表示・操作できます。
新しい版が出たときは画面下に案内が出ます。「再読み込み」を押すまで切り替わらないので、
入力途中の内容が消えることはありません。

## アクセシビリティ

キーボードだけで操作できます。カレンダーは矢印キー、Home / End、Page Up / Down で
日と月を移動できます。冒頭に「本文へ移動」のスキップリンクがあります。
主要画面は axe-core（WCAG 2.1 AA）の検査を CI で通しています。
