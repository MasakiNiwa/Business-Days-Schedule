# Business Days Schedule

**営業日/決算月を反映した反復ルールを組んで、Outlook / Google カレンダーへ。**

日本の祝日を自動で取り込み、**反復ルール**（毎月25日／月末営業日／第5営業日／第2・第4火曜 など）から
予定を導出し、休祝日にかかった予定を**前営業日・翌営業日へ自動でずらして**表示します。
組んだルールは iCalendar (.ics) / CSV で書き出し、会社で使っているカレンダーへ取り込めます。

「毎月25日、ただし休業日なら前営業日」のような予定は、Outlook や Google カレンダーの
繰り返し設定では表せません。**そこを組み立てるのがこのアプリの役目**で、
日々見るのは会社のカレンダーのままで構いません。

ルールを持たない単発の予定登録は、意図的に対象外としています。

- 📄 **[仕様書 docs/SPEC.md](docs/SPEC.md)**

**公開先**: https://masakiniwa.github.io/Business-Days-Schedule/

|---|---|

サンプルは種類ごとに分かれており（基本セット／税務・届出／売上・入金／支払・振込／会議・報告）、
**使い始めたあとでも追加できます**。「内容を選ぶ」で必要な予定だけ追加できます。追加しても既存のルールは消えません。
それぞれにグループが付いているので、追加した直後からグループで絞り込めます。

## 使い方

1. **ルールを追加** — 給与・支払・締め日・会議・自由入力のひな型から始め、
   休業日にあたったときの補正（前倒し・後ろ倒し・**前後の両方**・近い方・補正なし）を決めます。
   保存欄に設定の要約と直近3回の日付が出ます。必要なら「次の10回をすべて見る」を開けます。
   取引先ごとに前倒し・後ろ倒しが分かれる入金予定などは「前後の営業日の両方へ」を選ぶと、
   1つのルールで両側を押さえられます。
2. **月を移動する** — 年月の両横の `‹` `›`、または年月をクリックして月を選べます。
   スマートフォンではカレンダーを左右にスワイプしても移動できます。
3. **カレンダーを読む** — 補正された予定には `←10` `→10` が付きます。`←` は前倒し、
   `→` は後ろ倒し、数字は補正前の日です。予定名は省略せず、セルは中身に合わせて伸びます。
   セルのどこをクリックしても当日の詳細が開きます。

   カレンダーの上の **表示** で、予定の出し方を切り替えられます。

   | 出し方 | 中身 | 向いている場面 |
   |---|---|---|
   | 内容（既定） | 予定名まで出す | 何があるかをその場で読みたい |
   | 点 | 色の点だけ。件数は点の数で分かる | 1か月を見渡したい・スマートフォンで幅が足りない |

   選んだ出し方は次に開いたときも残ります。点にしたときは、日付を押せばその日の
   予定を省略なしで読めます。一覧表示へ切り替えても読めます。
4. **グループで束ねる** — ルールに「税務」「入金」のようなグループを付けると、
   カレンダーの上の **グループ** でその束だけを表示できます。
   サンプルにはあらかじめグループが付いています（基本／税務／売上・入金／支払・振込／会議・報告）。
   グループで絞っているときに新しいルールを足すと、その束の続きとして作られます。
5. **営業日を定義** — 右上の設定（⚙）から、週末の曜日・祝日を休むか・年末年始などの休業期間・
   臨時休業日・祝日出勤日を指定します。「自社」と「銀行」を別々に持てるので、
   社内の締めと振込を使い分けられます。
6. **決算月を設定する** — カレンダーのすぐ上の
   〈自社カレンダー: 営業日◯日 / 休業日◯日 ・ 決算月◯月〉を押すと設定が開きます。
   「決算月」を変えると、`決算月基準` のルール（法人税・消費税の申告、期首、中間申告、
   四半期末）の日付が**まとめて追従します**。3月決算なら申告期限は5月末、
   12月決算なら翌年2月末、というように自動で変わります。

   暦月で書くと決算月が変わったときに全ルールを直して回ることになるため、
   決算月を設定として持ち、そこからの相対で表しています。

7. **前後の予定を付ける** — 1つのルールに、本体の**前**（準備日）と**後**（フォロー）の
   予定をぶら下げられます。起点は営業日補正のあとの確定日なので、本体が動けば
   前後の予定も一緒に動きます。

   | 向き | 例 |
   |---|---|
   | 前（準備） | 給与振込の3営業日前に「振込データ作成」 |
   | 後（フォロー） | 請求書発行の5営業日後に「送付済みの確認」、入金予定日の翌営業日に「入金の確認」 |

   日付の決め方は3通りあり、件ごとに選べます。日数だけでは「翌週の水曜」のような
   実務の言い回しを写せないためです（本体が週のどこにあるかで日数が変わります）。

   | 決め方 | 書けること |
   |---|---|
   | 日数で指定 | `3営業日前` / `5営業日後`。営業日・暦日を選べます |
   | 週と曜日で指定 | `翌週の水曜 / 休業日なら翌営業日へ`。週は月曜始まりで、本体のある週が基準です |
   | 月と第N営業日で指定 | `翌月の第5営業日`。〈月初から／月末から〉を選べます（月末から1営業日目＝最終営業日） |

   「休業日なら翌営業日へ」は**その日以降の最初の営業日**まで送ります。水曜が休みで
   木曜も休みなら金曜です。「木曜へ固定」ではありません。設定欄の下に決まった内容が
   文章で出て、実際の日付はプレビューで確かめられます。

   その月に営業日が足りないなど、日付を決められない回はプレビューに
   **「計算できません」と理由ごと残ります**（「2026年10月には月初から25営業日目が
   ありません」）。黙って消えることはありません。

   別々のルールとして作ると、本体だけ動いたときに取り残されます。メールやプッシュ
   通知は送らず、カレンダー上に予定として出るだけです。
8. **一覧で先を見る** — 右上の「一覧」に切り替えると、今日から 30／90／180／365 日先までの
   予定が時系列で並びます。日付をクリックすればその日の詳細、予定名をクリックすれば
   そのルールの編集が開きます。
9. **印刷する** — カレンダー・一覧のどちらもそのまま印刷できます。操作ボタンは省かれ、
   白地・黒文字で出力されます。アプリ名と版は印刷しません（年月・予定・営業日数・出典は残ります）。
10. **会社のカレンダーへ取り込む** — 右上の **書き出し** から、期間を指定して
   iCalendar (.ics) または CSV で書き出せます。Google カレンダー・Outlook などに取り込めます。
   繰り返しの設定そのものは渡らず、その期間の日付として展開されるので、
   期間が過ぎたら書き出し直してください。自動では同期されません。

   初期値は**今月1日〜末日**です。試しに押した1回で1年分がメインの予定表へ流れ込むと
   消して回るのが大変なため、短い期間から始まるようにしています。
   **グループ単位でも書き出せます。** 画面で絞り込んでいるときはその束が初期値になり、
   カレンダー名とファイル名にも束の名前が入ります。取り込み先でも束ごとに分けておくと、
   あとで丸ごと消せます。
   **取り込み先は専用のカレンダーを作ってからにしてください**（Outlook なら
   「カレンダーの追加 → 空のカレンダーを作成」、Google カレンダーなら
   「他のカレンダー ＋ → 新しいカレンダーを作成」）。丸ごと消せるようになります。

   取り込んだ先では次のように並びます。

   | 出しかた | 例 |
   |---|---|
   | そのままの日 | `給与振込` |
   | 休業日で前へ動いた | `給与振込（繰上）` |
   | 休業日で後ろへ動いた | `給与振込（繰下）` |
   | 準備日 | `【振込データ作成】給与振込` |

   分類（カテゴリ）に「Business Days Schedule」が付くので、Outlook では色分け・絞り込みや、
   試しに入れた予定をまとめて消すときの手掛かりになります。
   予定は終日・空き時間扱いなので、予定表の時間を埋めません。
11. **バックアップ** — 設定の「エクスポート」で JSON に書き出せます。
   データはブラウザの localStorage に保存されるため、端末を移るときは書き出してください。

ルールの一覧・追加、サンプルの追加は右上の **ルール** ボタンから開きます。
配色は **◐** ボタンで 自動 / ライト / ダーク を切り替えられます。
操作に迷ったら **?** ボタンから画面内ヘルプを開けます。ヘルプは
「このアプリは何をするもの？」「はじめの3ステップ」から
「思ったとおりに出ないとき」まで節に分かれており、先頭の目次から直接飛べます。

## 祝日データについて

一次ソースは [`holiday-jp/holiday_jp`](https://github.com/holiday-jp/holiday_jp) の `holidays.yml`
（UTF-8、1970〜2050年、振替休日・国民の休日を収録）。
内閣府CSVへの依存はありません。毎週月曜03:17（日本時間）を予定時刻として、
取得・検査したデータを**アプリ本体へ同梱**してGitHub Pagesへ公開します。

**起動時にデータを取りに行きません。** 祝日データはデプロイのたびに作り直される
ビルド成果物であり、別ファイルとして取りに行っても中身は同じ版のままです。
得られるものが無いのに、初回表示までの通信が1往復増えるだけなので、同梱に切り替えました。
低速回線を模した測定では、速くなる場合で約440ms（3往復ぶん）縮み、遅くなることはありません。

同梱するのは**出典の全期間**（1970〜2050年・1,329件・48KB、gzip で約5KB）です。
年を絞ればファイルは小さくなりますが、絞った外の年を開くと「収録範囲外」の警告が
出てしまうため、遡って見られるよう全期間のまま持ちます。
詳細は [仕様書 §3](docs/SPEC.md#3-祝日データ)。

## 開発（続き）

```bash
npm run e2e:install  # E2E 用ブラウザの用意（初回のみ）
npm run e2e          # 本番ビルドに対するブラウザテスト
```

E2E は `dist/` を素の静的配信で動かします（`scripts/serve-dist.ts`）。
GitHub Pages と同じ条件に近づけ、公開後にだけ壊れる不具合を拾うためです。

## 外部カレンダーへ再取り込みするとき

ICS/CSVは自動同期ではなく、書き出した時点の予定です。取り込み先によって再取り込みの動作は異なります。

v1.1.0 ではICSの予定識別子を変更したため、v1.0.x から持ち越した予定とは重複しえます。
専用カレンダーで入れ替えるなど、取り込み先で確認してください。

v1.2.0 以降は識別子を変えていません。iCalendar (.ics) の予定には内容から決まる
識別子が付いているので、**取り込み先がそれを見て同じ予定と判断すれば**更新されます。
ただし更新になるか二重に増えるかは取り込み先の実装しだいで、こちらからは保証できません。
CSV には識別子そのものがありません。まずは短い期間で試し、増えないことを確かめてください。

**このアプリで消した予定は、取り込み先では消えません。** 書き出しは「その時点の
予定の写し」で、取り消しの情報を含みません。ルールを削除・無効化しても、既に
取り込んだ予定は残ります。専用のカレンダーへ取り込んでおけば、そのカレンダーごと
消して入れ直せます。

## オフライン対応

一度開いたあとは、通信が無くても表示・操作できます。
新しい版が出たときは画面下に案内が出ます。「再読み込み」を押すまで切り替わらないので、
入力途中の内容が消えることはありません。

## アクセシビリティ

キーボードだけで操作できます。カレンダーは矢印キー、Home / End、Page Up / Down で
日と月を移動できます。冒頭に「本文へ移動」のスキップリンクがあります。
主要画面は axe-core（WCAG 2.1 AA）の検査を CI で通しています。
